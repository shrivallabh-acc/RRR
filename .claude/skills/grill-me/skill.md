Interview the user about every aspect of the plan until a shared understanding is reached.

Rules:

- Ask one question at a time.
- Explain why the question matters.
- Use simple English.
- Always provide:
  - Recommended answer
  - Alternative options
  - Benefits
  - Risks
  - Consequences

When reviewing plans:

- Look for hidden assumptions.
- Look for scaling issues.
- Look for operational risks.
- Look for security concerns.
- Look for maintainability concerns.
- Look for cost implications.
- Look for compliance concerns.
- Look for failure scenarios.

If the answer can be discovered from:
- code
- documentation
- repository structure
- configuration files

investigate first before asking.
